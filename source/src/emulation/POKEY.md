# POKEY emulation

Atari POKEY audio for Centipede. Code: `source/src/emulation/pokey.{h,cpp}`,
tables: `source/src/emulation/pokey_poly.h`, generator:
`romconv/internal/pokey_poly.py`.

Port of MAME `devices/sound/pokey.cpp`, restructured for the ESP32: event
driven instead of per clock, compact tables, poly17 generated on the fly,
audio and RANDOM only.

## Chip

- 4 channels: AUDFx (8 bit divider), AUDCx (volume bits 0-3, VOLUME_ONLY
  bit 4, distortion bits 5-7).
- AUDCTL: base clock / 28 (64 kHz) or / 114 (15 kHz); ch1/ch3 at full chip
  clock; ch1+2, ch3+4 joined as 16 bit dividers; ch1/ch2 high-pass filters.
- Poly counters (LFSR) of 4, 5, 9, 17 bits, stepped every chip clock. A
  divider borrow toggles the output (pure) or samples a poly bit (noise).
  Poly5 can gate borrows.
- High-pass filter: ch3 borrow latches ch1 output; audible = ch1 XOR latch
  (ch4/ch2 alike).
- RANDOM: top 8 bits of poly17 (or poly9). SKCTL bits 0-1 clear = reset,
  polys held.
- Output: unipolar sum of volumes of channels currently high.

Centipede clock: 12.096 MHz / 8 = 1.512 MHz, same as the 6502.

## Tables

Generated by `pokey_poly.py` (port of MAME `poly_init_4_5` /
`poly_init_9_17`). All `const`, in flash, no RAM.

| Table    | Period | Stored as                     | Size    |
| -------- | ------ | ----------------------------- | ------- |
| poly4    | 15     | output bits in a `uint16_t`   | 2 B     |
| poly5    | 31     | output bits in a `uint32_t`   | 4 B     |
| poly9    | 511    | full states, `uint16_t[511]`  | 1022 B  |
| poly17   | 131071 | none, generated (`pokey.cpp`) | 0       |

poly9 keeps full states: RANDOM in poly9 mode is `state & 0xff`.

## poly17

MAME stores all 131071 full states (512 KB). An output bit table needs
16 KB. It does not compress: maximal-length LFSR output looks random to
deflate (16384 B -> zlib 16397 B, lzma 16444 B), and unpacking would
cost 16 KB Arena RAM anyway. So the bits are generated instead: no
table, 12 B state per chip, 16112 B flash saved.

The output bits o[n] (bit 0 of MAME state n) follow

```text
o[n] = o[n-12] ^ o[n-17]        characteristic poly x^17 + x^5 + 1
```

A 17 bit window `s` holds `o[p] .. o[p+16]`. Up to 12 new bits come from
bits already in the window, so `advance17(s, k)` moves it k <= 12 bits
with 3 shift/xor ops. `POLY17_START` = `o[0..16]` = 0x0007f.

- Channel noise (sequential): per sample, while not in reset,
  `window17()` builds `w17` = `o[p] .. o[p+63]` (5 x 12 + 3 bits of
  advance) and moves `s17` 63 bits on. `event()` at offset t reads
  `(w17 >> t) & 1`.
- RANDOM (random access): `state17_at(i)` jumps via
  `x^i mod x^17 + x^5 + 1` (17 square-and-multiply steps). With
  `x^i = sum r_k x^k`, `o[i+m] = XOR of o[k+m]` over set `r_k`, taken
  from `o[0..40]`. About 17 carry-less 17 bit multiplies per read; RANDOM
  is read a few times per frame.

Bits 8..16 of the MAME poly17 state only shift, so bit k of state i is
output bit `i-17+k`; RANDOM (bits 8..15) is output bits `i-9 .. i-2`
(`RANDOM17_LAG`), i.e. the low byte of `state17_at(i-9)`.

Host test (`test_pokey`) checks both paths against MAME's states:
`window17` over 2 periods, `state17_at` at every position.

## Emulation

One 24 kHz sample = 63 chip clocks (`CLOCKS_PER_SAMPLE`).

Per `render()` call (64 samples): read registers, compute each channel's
period in chip clocks:

- normal: `(AUDF+1) * 28|114`
- high clock: `AUDF + 4`
- joined: `AUDF16 + 7` (high clock) or `(AUDF16+1) * base`; low channel off

A counter longer than the new period restarts with it.

Per sample, per channel (order 3, 4, 1, 2 as in MAME `step_one_clock`):

```text
while counter < 63:
    add clocks spent high since last event
    event() at offset counter     // pure toggle or poly bit, poly5 gate
    ch3/ch4 borrow: latch ch1/ch2 filter
    counter += period
counter -= 63
```

Sample value = sum of `volume * clocks high`. Work scales with borrows,
not clocks, and the per-sample average is a box filter (cheap
anti-aliasing). Poly positions are kept per sample start; an event at
offset t reads position `i+t`, all advance by 63 per sample while not in
reset (poly17: window `w17`, see above).

Channels whose borrows are inaudible (volume 0 or volume only, and not
clocking an enabled ch1/ch2 filter) skip the loop; their counter advances
once per buffer. Idle Centipede keeps ch3 at a 4 clock period, ~9000
borrows per frame without this.

Output stage (not from MAME): scale to 0..960, DC blocker (2^9 samples),
one-pole low pass ~4.8 kHz (board opamp stage), clamp +-511.

## RANDOM

Stateless (`Pokey::random()`), called from the CPU read handler. Since CPU
and POKEY clocks match, POKEY clock = CPU cycles since SKCTL left reset
(`random_base`); 0 while in reset. Centipede reads RANDOM twice during
reset and requires equal values, else it inflates credits and traps in its
IRQ handler (0x38ac).

## Differences from MAME

- Event driven with box-filter integration, not per-clock stepping.
- Fixed 63 clocks per sample: only 1.512 MHz chips at 24 kHz.
- poly17 generated from its recurrence, no table.
- RANDOM from CPU cycle count, no poly state on the CPU side.
- No pots, keyboard, serial, timers, IRQs.
- Linear volume sum plus custom DC blocker and low pass.
- Filter latch accurate to one sample (ch1 sees ch3's latest latch of
  that sample).
- Registers sampled once per 64-sample buffer (~2.7 ms).
- Muted pure tone channels lose their phase.
